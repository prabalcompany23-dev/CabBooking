# BRD — Playo Book-a-Ride

**Source of truth:** [../../BRD_Book-a-Ride_Phase1_Phase2.docx](../../BRD_Book-a-Ride_Phase1_Phase2.docx)  
**L2 build (R1):** [release-R1-build-scope.md](../../release-R1-build-scope.md) (BR-01 – BR-05)

## Business context (summary)

Playo books sports venues but not transport. Book-a-Ride closes the gap; Phase 1 validates demand before automation.

## Objectives

- Extend journey to include ride to venue  
- Commission revenue (later phases)  
- Convenience / stickiness  
- Validate demand before full integration  

## Phase 1 business requirements

| ID | Requirement |
|----|-------------|
| BR-01 | User can indicate need for a ride after venue booking |
| BR-02 | Fulfil requests via manual, low-cost process |
| BR-03 | Log every request to measure demand |
| BR-04 | User understands payment is **outside app** in Phase 1 |
| BR-05 | Cancelled/rescheduled game updates linked ride request |

## Release R2 (not in current L2 build)

BR-06 – BR-10 (fare estimate, in-app book/pay, tracking, reporting link, ratings) — see Word BRD.

## Success metrics (Phase 1)

- Requests received and successfully fulfilled in pilot  
- Request rate as % of eligible bookings  

## Out of scope (Phase 1 & 2)

Group/shared vehicle, carpooling, areas outside approved pilot/MVP coverage.
